# min-script　方案 → 内容草稿 → 内容正稿

## 一、内容正稿的定义

送审和下游只用 `内容稿.md`。它必须是一篇**完整文章**：

- 不依赖方案、PPT、视频或老师补充说明，也能独立读懂。
- 标题提出的问题或承诺，正文必须正面回答并完整兑现。
- 有明确主旨、连续论证、充分解释、具体案例或演示、可执行方法和必要边界。
- 去掉文件头元数据后，只需做平台排版即可发布为公众号长文。
- 能作为 PPT、口播、公众号、小红书等全部下游内容的唯一事实母稿。

以下产物一律不算内容正稿：分页口播稿、只有口号的提纲、把方案换个说法抄一遍、必须看 PPT 才能懂的半成品。

`内容稿草稿.md` 用同一套文章标准来写，但是中间文件，不送审。

## 二、输入与输出

只读取已通过方案关的 `10-内容稿/方案.md`。

```text
10-内容稿/内容稿草稿.md          大模型按方案写的草稿。不打开知识库
10-内容稿/内容稿.md              正稿。奇门知识库校正冲突之后的全文
10-内容稿/知识校准简报-正稿.md    备查，不送审
Gate-S2内容稿.md
```

人只看正稿。草稿和简报不送审。

## 三、两步，缺一不可

任何选题都要走完这两步。知识库没写到这个题目，不是停稿的理由。

### 1. 写草稿

不要打开 `knowledge/`，不要调用 `min-review`。

按方案写成完整文章。草稿里的定义、因果、规则可以和大模型自己的理解一致，也可以和知识库不一样。先把课写完，不要边写边对着知识库改，也不要因为「库里没有」就拒绝成稿。

仍要守住方案里的受众、核心观点、内容边界和页表标题。不编造可核对的数据来源；教学假设标成假设。

### 2. 用奇门知识库校正成正稿

草稿落盘后，读取并执行 `Skills/min-review/SKILL.md` 与 `RULES.md`。

- 奇门课只读 `knowledge/yizheng-qimen`。八字课只读 `_state.md` 里的 `kb_root`。
- 材料是草稿，不是正稿。
- 和知识库明确不一致的地方，按知识库改正，写入 `内容稿.md`。
- 只改草稿里和奇门知识库明确冲突的奇门遁甲内容，写入正稿。其它内容以草稿为准：知识库没写到的、只覆盖一部分又不能证明其余是错的，都保持草稿原句。不要用模型自己的知识改稿。
- 草稿文件保留，不要覆盖。
- 正稿保持草稿的结构、页标题、顺序和篇幅。只改知识冲突，以及为了上下文成立必须一起改的句子。

## 四、边界

- 不改变方案中的受众、核心观点、内容边界和论述结构。
- 方案里的核心模块、练习与互动、小结必须写进文章。
- 不拆 PPT 页面。不写页任务、上屏字、逐页口播或视觉建议。
- 不写平台专属关注、评论和购买话术。
- 不出图、配音、字幕或成片。
- 不为凑字数重复同一结论。

## 五、写作要求

方案里如果有页表，草稿和正稿都按页表写：每个标题必须是 `## 第01页｜这一页只做的那件事`，顺序和文字都跟页表一致。不要另起引言、一二三四五和结语。参考与说明可以写在最后，不占页。

没有页表的旧课，仍按引言、正文各节、结语、参考与说明来写。

1. 文头填齐课名、课程目标、学员、内容定位和不讲。
2. 从用户处境进入，建立明确阅读价值。
3. 用完整章节展开观点、原理、案例、方法、误区和应用。方案里的练习与互动必须写成读者能做的练习、填空或清单。
4. 每个关键结论给足解释与限定，不只列知识点。
5. 专业术语第一次出现时用白话说明。能当名字记住的 2～4 字，必须已经出现在本课知识库、谷子逐字稿，或 `_state.md` 的课程目标里。没有来源写成整句，不要新造。正稿阶段若草稿新造了名字，改成整句。`qa_script.py` 只查正稿。
6. 案例真实可授权、匿名，或明确标注教学假设／虚构。
7. 结语只收束全文，不增加新核心观点。
8. 参考与说明写明资料依据、案例性质和必要免责。

写完草稿后做三次自检，再进入校正：像文章吗、每节都在回答标题吗、读者看完真的会了吗。

## 六、完成标准

以下条件必须**全部满足**，才可写 `Gate-S2内容稿.md` 并送审正稿：

- [ ] `内容稿草稿.md` 已落盘，且写草稿时没有打开知识库。
- [ ] 已执行 `min-review`。明确冲突已改入正稿。知识库没覆盖的部分仍留在正稿里。
- [ ] `知识校准简报-正稿.md` 已写好。待人工项只进简报，不挡成稿。
- [ ] 正稿是完整文章，受众、观点、边界与已通过方案一致，标题被正面兑现。
- [ ] 方案中的练习已写成读者能做的练习、填空或清单。
- [ ] 至少有一个具体案例、教学示例、事实论证或完整应用推演。
- [ ] 去掉元数据后可直接排版发布。没有「这一页、上屏字、停几秒」等制作语言。
- [ ] `qa_review.py` 与 `qa_script.py` 都是 `errors=0`。

## 七、总流程

正稿已经通过 `qa_script.py` 和 `qa_review.py`，且内容稿关没有被驳回：不再重写，直接等人审。

否则按下面的顺序走，正稿和简报各只写两稿，两条检查各只跑两遍。文件没改，就不要再审。同一条 ERROR 第二次还在就停，不要整篇重写。若磁盘上还有一份已经通过的正稿，恢复那一份。

```text
已通过方案
  → 不打开知识库，按方案写内容稿草稿.md
  → 文章 / 扣题 / 兑现自检
  → min-review：只改和奇门知识库明确冲突的句子，写入内容稿.md，草稿保留
  → 写知识校准简报-正稿.md
  → qa_review.py 一次
  → qa_script.py 一次（只查正稿）
  → 有 ERROR：只改点名的那几句，两条检查再各跑一次
  → 通过后写 Gate-S2内容稿.md
  → 停下等教研审核正稿
```

机器检查只认硬伤：文头、页表、篇幅、案例、练习、制作用语、新造专名。讲得准不准、深不深，由教研在待审里判断。检查通过不是把课写满的许可。

```text
python Skills/min-review/scripts/qa_review.py projects/<课名>/10-内容稿/知识校准简报-正稿.md
python Skills/min-script/scripts/qa_script.py projects/<课名>/10-内容稿/内容稿.md
```

审核通过后，正稿冻结。任何知识、事实、案例、逻辑或重要限定的修改，都必须重新打开内容稿关，并使 PPT 大纲、PPT、口播稿、成音、字幕和成片全部重新生成。驳回重写时，从草稿改起，再校正一次。
