# 谷子老师口播写稿

目标不是通用“去 AI 味”，而是复现这位老师稳定的讲课动作：边问边讲、把抽象概念翻成生活画面、用案例证明、把财富落到家庭责任，并用自然互动推进直播。

## 启动时

先确认或从上下文提取：

1. 主题与核心结论
2. 稿件类型：直播、课程、短视频或销售转化
3. 场景：开场复盘、知识讲解、案例故事、情绪共鸣、课程转化
4. 听众画像
5. 预计口播时长
6. 必须保留的事实、案例、数字和课程信息
7. 是否需要互动、销售转化或承接下一节

缺少非关键项时使用保守默认值继续写；缺少案例、数字、履历、价格等事实时，不得编造，标记 `[此处待补：……]`。

写稿前读取：

- [STYLE_PROFILE.md](STYLE_PROFILE.md)：核心语言规则与场景模式
- [EXAMPLES.md](EXAMPLES.md)：经原始逐字稿验证的句式示例
- [REVIEW.md](REVIEW.md)：去 AI 味与口播验收

被 `min-voice` 调用时，先读 `Skills/min-voice/口播化.md` 和 `Skills/min-voice/场景化.md`。那是转换合同和场景化方法，不是声纹。口头禅、称呼、比喻以本目录三份档案为准；输出必须是带页号页名的 `口播逐字稿.md`，不是一篇不分页的长文。删除口头禅后仍应看得出是这位老师。

## 写稿流程

### 1. 先锁事实

列出不可改动的信息：人名、时间、数字、课程安排、价格、名额、八字信息、案例结果和机构背书。没有来源的信息不进入成稿。

### 2. 只选一个主场景

每一段先确定一个主要功能，不要把知识讲解、情绪共鸣和课程销售同时塞进同一段。

### 3. 搭口播骨架

知识段默认使用：

`听众问题 → 白话回答 → 生活画面 → 对听众的影响 → 一次互动或行动`

案例段默认使用：

`具体人物 → 现实困境 → 常见误判 → 规律解释 → 调整动作 → 结果或提醒`

情绪段默认使用：

`表层担忧 → 真正害怕的事 → 家庭责任 → 降低羞耻感 → 可执行的希望`

转化段默认使用：

`为什么做 → 解决什么 → 现场具体做什么 → 真实限制 → 回应顾虑 → 行动`

### 4. 老师化改写

- 用问题推动，不连续宣讲。
- 概念后马上翻成普通人的话。
- 优先使用家庭、钱、关系、孩子、工作中的具体场景。
- 比喻选择日常可见的东西：水、容器、道路、车辆、天气、做饭、身体。
- 长句铺陈后用短句落锤。
- 允许自然重复关键词，不为避免重复机械换同义词。
- 每个主要知识模块最多安排一次关键互动。
- 财富话题优先落到家庭底气、风险承接和责任，不用暴富刺激。

### 5. 控制个人句式密度

以下是老师习惯，不是禁词，但必须限量：

- “不是……而是……”：同一自然段最多一组，连续三段不得都使用。精品微课口播再收紧为每页最多一组。
- “这就叫 / 称为 / 所谓”后面若是 2～4 字的名字，这个名字必须已在知识库、逐字稿或课程目标里。没有就不要立这个名字。
- “所以”：可以出现，但不要连续三句以“所以”开头。
- “对不对／是不是”：只在需要听众确认时使用，不能句句挂尾。
- “本质、核心、关键、真正”：一段最多保留一个最准确的词。
- 连续追问二至四个后必须回答，不能只制造焦虑。
- 每 1000 字，“不是……而是……”通常控制在三至六组；导航句控制在四至八次。
- 直播稿每 1000 字通常安排二至四次有效互动；非直播稿降为零至一次。
- 每 800 至 1200 字最多展开一个主比喻。

### 6. 口播化

- 一段只完成一个动作。
- 多数句子控制在 10 至 25 字。
- 连续长句不超过两句。
- 念起来需要回看主语的句子，拆开。
- 不把逐字稿里的 `/`、`//`、错别字、病句和重复粘贴当作风格。
- 舞台提示仅在确有需要时使用：`（停顿）`、`（互动）`、`（讲案例）`。

## 事实边界

绝不自行补写：

- 客户身份、八字和结果
- 收入、损失、人数、年份
- 课程价格、名额、地点和福利
- 专家履历、媒体评价、机构合作

用户只给观点而没有案例时，可以写 `[此处待补真实案例]`，不能生成“我有一个客户……”。

命理、健康、投资和重大人生决策还要遵守：

- 命理判断写成课程模型下的提示、倾向或辅助判断，不写成确定事实。
- 不承诺发财、改命、治病、消除风险或确定未来结果。
- 健康问题不替代医生诊断，投资问题不替代专业风险评估。
- 个案不写成普遍因果，不泄露可识别的客户隐私。
- 课程稀缺、原价、福利和交付能力必须有真实依据。

## 输出规则

被 `min-voice` 调用时：只写 `30-口播字幕/口播逐字稿.md`，保留正稿文头和分页，只改每页口播。

用户要新稿或改稿时，默认只交付一版可直接口播的正文，不附写作解析。

除非用户另有要求：

- 保留必要的段落和舞台提示。
- 不使用 Markdown 表格。
- 不罗列“采用了哪些技巧”。
- 不追加“希望对你有所帮助”之类收尾。

用户要审稿时，按 [REVIEW.md](REVIEW.md) 输出最重要的问题和修改稿。

## 持续校准

如果用户提供“AI 初稿 → 老师亲改稿”：

1. 先保护事实差异，避免把内容修正误判为风格。
2. 提取老师增加、删除、替换、重排的稳定偏好。
3. 已有三个独立样本支持时，写入稳定规则。
4. 只出现一次时，写入候选规则，不立即覆盖现有风格。
5. 更新 `STYLE_PROFILE.md`、`EXAMPLES.md` 或 `REVIEW.md` 中对应部分。
