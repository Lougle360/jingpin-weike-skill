# 精品微课写前查重

写设计前只查一件事：**以前有没有发布过这样的文章或课。**  
这一步**不打开知识库**。知识库核对只在正文写完后走一遍，不归本 Skill。

## 去哪查

只看已经做出来或已经发布的篇目，不翻 `knowledge/`。

1. `projects/` 每门课的 `_state.md`：课名、课程目标。已过看片或已有成片的，算发过。
2. 同目录的 `10-内容稿/方案.md`、`10-内容稿/内容稿.md`：标题、主旨。
3. `Skills/min-plan/examples/` 里的样例课。
4. 人另外点名的已发清单（若有）。

本课自己的目录不算撞题。

## 三种结论

| 以前发过没有 | 能不能写 | 什么时候 |
|---|---|---|
| 未发过 | 能 | 课名、目标、主旨对不上已有篇目 |
| 邻近同题 | 能 | 题目接近，但切口不同；主旨里写清新切口，方案关让人看一眼 |
| 同题已发 | 停回流 | 同一学习目标或同一篇再做一遍 |

同题：课名相近，且课程目标在教同一件事。  
邻近：都谈煞、伏吟、印星，但要带走的能力不同。不准把邻近写成同题来挡课。

## 怎么记

评估表只填这三格：

| 项 | 填法 |
|---|---|
| 以前发过没有 | 未发过 / 邻近同题 / 同题已发 |
| 能不能写 | 能 / 停回流 |
| 已有篇目 | 未发过写「无」；否则写课名或相对路径 |

不要填「库里有没有」「给养文件」「匹配度」。写前不准打开 `knowledge/`。

## 和写后校准的分工

| | 写前查重 | 写后校准 |
|---|---|---|
| 何时 | 写方案之前 | 内容稿草稿写完之后 |
| 问 | 以前发过没有 | 草稿和知识库有没有明确冲突 |
| 同题已发 | 回流，不出设计 | — |
| 知识对错 | 不管 | 不归本 Skill |
