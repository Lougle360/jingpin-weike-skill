# 示例知识库

这是一个**空骨架加六个范本组件**，用来说明知识库该长什么样。里面的家庭教育内容只是格式示范，不是可直接开课的知识资产，请换成你自己的。

知识库对 Agent 只读。写方案和内容稿草稿时不打开它；草稿写完后由 `min-review` 拿它校正明确冲突，生成内容正稿。库里没覆盖的选题仍然成稿，不会被拒。

## 目录结构

```text
knowledge/<库名>/
├── README.md              本文件，说明这个库讲什么、边界在哪
├── kb-profile.yaml        库的元数据：覆盖范围、不覆盖范围、版本
├── 01-索引/
│   ├── 总课程导航.md       Agent 检索的第一入口
│   └── 组件总表.md         全部组件一览，带 ID 和路径
├── 02-概念/               这个领域的基本概念，回答「这是什么」
├── 03-原理/               机制和因果，回答「为什么会这样」
├── 04-观点/               有立场的主张，回答「我们怎么看」
├── 05-误区/               常见错误认识，回答「别人通常怎么想错」
├── 07-框架/               多要素的结构化模型
├── 08-规则/               可判断可执行的具体规则
├── 10-案例/               真实或明确标注为虚构的案例
└── 14-边界/               这个领域不管什么，什么时候该转介
```

类型目录可以按你的领域增减，但**必须有 `01-索引/`**，否则 Agent 找不到入口。

## 一个组件长什么样

每个组件是一个独立 markdown，开头是 YAML front matter，正文是可直接引用的内容。参照 `02-概念/概念-有效陪伴.md`。

front matter 字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 全库唯一，建议 `库名.类型.短名`，只在后台用，**不许写进学员可见正文** |
| `type` / `type_cn` | 是 | 组件类型，和所在目录一致 |
| `title` | 是 | 组件标题 |
| `summary` | 是 | 一两句话说清这个组件讲什么，Agent 检索主要看这里 |
| `source_file` | 建议 | 这条知识从你哪份原始资料来的，便于追溯 |
| `evidence_level` | 建议 | `原文主张` / `行业共识` / `编者归纳`，标清可信度 |
| `status` | 建议 | `已整理` / `待补充` |
| `depends_on` | 否 | 理解本条前需要先懂的组件 ID |
| `related` | 否 | 相关组件 ID |

正文用小标题分段，每段说清一件事。不要写成大段散文，Agent 摘取会困难。

## 从现有资料建库

如果你手上是课件、讲稿、Word 或公众号文章，需要先做一遍**组件化**：把连续的讲稿拆成一条条独立成立的知识点，每条补上 front matter，再汇总进 `01-索引/组件总表.md`。

这件事的工作量取决于原始资料的量和结构化程度，通常是整个项目里最花时间的一步，建议单独安排。拆的时候守两条：一个组件只讲一件事；脱离上下文单独读也要成立。
