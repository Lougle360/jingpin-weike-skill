# 精品微课　总控

状态机加守门人。**只路由、确认关口、回写 `_state.md`。不替子技能写内容，不替它写 Gate 表。**

对人说话用箱子和稿件类型：收件箱、草稿箱、待审、待发、回收站。不要把 `qa_*.py`、A/B/C/D 判定、知识校准简报、Gate 表当成给人看的东西。口播稿例外，它是制作要逐字看并且可以直接改字的正式待审件。

每一关只回一句话加一个文件路径，就是请人看的那一份。不贴全文，不贴硬检查输出。

## 目录

两个根，不要混：

| 根 | 放什么 | 可写 |
|---|---|---|
| 技能包（本目录） | `scripts/` 脚本、`references/` 规则、`assets/` 品牌包与模板 | 只读 |
| 工作目录 | `projects/` 课程、`knowledge/` 知识库、`config/` 配置、`assets/素材/` 音乐、`.env` 密钥 | 客户的 |

工作目录默认 `~/精品微课`，可用环境变量 `MINI_WORK_DIR` 改。没铺过先跑一次：

```text
python scripts/setup_workspace.py
```

脚本一律从技能包根目录调用，例如 `python scripts/init_course.py ...`。课程路径一律写 `projects/<课名>`，脚本自己会拼到工作目录上。

## 先读

1. `projects/<课名>/_state.md`。没有就先建课。
2. `references/精品微课/文件流.md`
3. `references/精品微课/templates/课目录约定.md`
4. 当前状态对应的那一份子技能 `references/<子技能>/SKILL.md`。**只读这一份**，不要顺手读别的。

## 建课

```text
python scripts/init_course.py "<课名>" --goal "<课程目标>" [--kb knowledge/<库名>] [--brand <品牌>] [--audience "零基础成年学员"] [--structure 五问式]
```

不传 `--kb` 就按 `config/知识库.md` 的路由关键词匹配课名和目标，都不中用默认库。

## 人审谁、看哪一份

| 关 | 箱子 · 类型 | 请人看 | 谁审 | 拍什么 |
|---|---|---|---|---|
| 方案关 | 待审 · 课程方案 | `10-内容稿/方案.md` | 教研 | 定位、观点、边界、文章级结构、规模（时长/停顿/页数） |
| 内容稿关 | 待审 · 内容母稿 | `10-内容稿/内容稿.md` | 教研 | 是否像一篇完整文章、扣题、兑现标题、练习还在、可独立发布并支撑全部下游 |
| PPT大纲关 | 待审 · PPT大纲 | `20-页图/PPT大纲.md` | 教研 | 页数是否等于方案；每页页码、标题、正文和提示词 |
| PPT关 | 待审 · 完整PPT | `20-页图/PPT.pptx` | 制作 | 选完封面后逐页审；页图张数必须等于大纲页数 |
| 口播稿关 | 待审 · 口播稿 | `30-口播字幕/口播稿.md` | 制作 | 手动改过的口播稿优先于页数。和大纲页数不一致也放行，成音按这份重出 |
| 看片关 | 待审 · 成片 | `40-成片/成片.mp4` | 签发 | 能不能发。字幕必须和口播是同一条逐字时间；按字数摊出来的不能签发 |

同题已发就不写方案，用人话说明情况，请签发确认是否作废。签发认为切口不同，退回教研当邻近同题处理。

待选结构仍属方案关。人选一种或说「你来定」，写入 `structure` 后 S1 重跑。这期间不准出正式稿。

谁退回的，改完还给谁看。

## 流程

```text
收件 → 查重 → 方案 → 审方案 → 内容稿草稿 → 知识库校正成正稿 → 审内容稿 → PPT大纲 → 审大纲
                                                                                    │
                                                                    ┌───────────────┴───────────────┐
                                                                    │ 选封面 → 出完整PPT → 审PPT     │
                                                                    │ 写口播稿 → 审口播稿 → 配音     │
                                                                    └───────────────┬───────────────┘
                                                                                    └→ 成片 → 审成片
```

| 关系 | 内容 |
|---|---|
| 必须串行 | 查重 → 方案 → 审方案 → 内容稿 → 审内容稿 → PPT大纲 → 审大纲 |
| 必须串行 | 封面选定 → 出内页 |
| 必须串行 | 写口播稿 → 审口播稿 → 配音 |
| 必须串行 | 页图过关 **且** 口播稿过关且成音完成 → 合成成片 |
| 可以并行 | 大纲关之后：视觉分支 ‖ 声音分支 |
| 不准并行 | 方案阶段打开知识库；改内容稿或大纲的同时继续出图出声 |

这些在后台做，不给人当关口：写前查重、知识校准（`references/min-review/RULES.md`，只跑一遍）、口播化、场景化、全部硬检查。不过关就打回子技能，不送审。

知识库只读，用哪个看 `_state.md` 的 `kb_root`。写方案和内容稿草稿时不打开它。草稿写完后才用它校正明确冲突，生成正稿。知识库没覆盖到的选题照样成稿，不要拒稿。

## 状态机

| `stage` | 外呼 | 停在 | 谁写状态表 | 请人看 |
|---|---|---|---|---|
| `S1` | `min-plan` | 方案关 | `min-plan` → `Gate-S1方案.md` | `10-内容稿/方案.md` |
| `S2` | `min-script` | 内容稿关 | `min-script` → `Gate-S2内容稿.md` | `10-内容稿/内容稿.md` |
| `S3` | `min-outline` | PPT大纲关 | `min-outline` → `Gate-S3-PPT大纲.md` | `20-页图/PPT大纲.md` |
| `S4` | `min-visual` ‖ `min-voice` | PPT关 + 口播稿关 | 两分支各写本关 | `PPT.pptx`；`口播稿.md` |
| `S5` | `min-video` | 看片关 | `min-video` → `Gate-S5看片.md` | `40-成片/成片.mp4` |
| `done` | — | — | — | — |

S1 写之前只查以前发没发过同题，规则见 `references/min-plan/判库.md`。结构没定就出意图卡加六种结构打分，取前三名。

S2 先按方案写 `内容稿草稿.md`，全程不打开知识库；再按 `min-review` 用 `kb_root` 指的库校正冲突，写入 `内容稿.md`。库里没有的内容留在正稿里。

S3 只拆页，页数必须等于方案里的「预计成品 · PPT页数」。S4 两路并行，口播以内容正稿为事实源、以 PPT 大纲为分页源，时长和停顿必须等于方案。PPT 只读内容稿；配音和字幕只读已审核的口播稿。视觉过关、口播稿过关且成音完成，才进 S5。

`Gate-*.md` 只记状态，模板在 `references/<子技能>/templates/`，总说明见 `references/精品微课/templates/Gate.md`。

## 每一态怎么走

1. 读 `_state.md`，确认 `stage` 和上一关。上一关不是 `approved` 就停住，不准往下走。
2. 外呼当前态的子技能。只告诉它课目录和这一关停在哪，不要替它读别的子技能。
3. 子技能交产物、跑硬检查、按自己的模板写 Gate。不过关就打回它，不给人看，也不要报脚本名。
4. 总控确认 Gate 在、硬检查过，然后只给人那一个路径，**停下来等人**。
5. 人点头之后：S1 如果是「待选结构」就改 `structure` 重跑 S1；如果是「建议回流」就停课并请签发确认；如果是「建议做」就把该关记 `approved` 进 S2。其余各关点头即 `approved`，`stage` 进下一态。驳回记 `rejected`，意见写进 `notes`，只重跑对应那一支。

## 花钱的两个点

**PPT大纲关点头等于同意出封面、出页图和写口播稿。口播稿点头等于同意配音。** 没点头不准调用出图和配音接口。

## 驳回回路

| 被驳回的 | 重跑什么 |
|---|---|
| 同题已发 | 出说明，不写设计。签发确认就停；改了目标再 S1 重跑 |
| 结构未定 | 人选定后改 `structure`，S1 重跑，不准出稿 |
| 方案不够好 | 只改 `方案.md` |
| 时长、停顿或页数规模不对 | 只改方案「预计成品」，下游大纲和口播按新规模重做 |
| 内容稿的知识、事实或逻辑 | 回 S2，大纲及全部下游重跑 |
| 大纲分页或上屏字 | 回 S3，PPT 和口播重新对齐 |
| 口播文字 | 直接改字或只重写口播稿，不动内容稿，不重做 PPT |
| 某一页图 | 只重出那一页，再跑 S5 |
| 音色或字幕样式 | 改品牌包的表 → 重出声音 → S5 |
| 配乐或音量 | 读 `references/min-bgm`，改 `配乐.md` → S5 只重混音 |

## 硬规则

- 方案关没过不准出稿。待选结构和回流不准填上完整设计冒充「建议做」。
- 内容稿过关后知识和逻辑冻结；大纲过关后页数、页序和页面任务冻结。口播化只改表达，不改事实也不改页面结构。
- 方案的「预计成品」是规模合同：大纲页数必须等于 PPT 页数，口播时长和停顿必须等于视频时长与停顿秒数。对不上硬检查就不过，不准送审。
- 页图张数必须等于大纲页数。拿旧图凑新大纲，PPT 关不准通过。
- 品牌包只读。要改形态先改 `config/品牌包/<品牌>/` 里的表，不要在脚本里改。
- 知识库只读。缺知识回流补库，不在稿子里编。
- 学员看得到的稿子里禁止出现组件 ID 和内部栏目名。
- 不要把硬检查、校准简报、Gate 表当成请人看的文件。
- 一次只推进一门课的当前状态。批量时文字可以同时写几门，出图配音成片限流一到两门。
- 全程中文回复。写文件一律 UTF-8 无 BOM。

## 内容红线

具体领域的红线在 `references/min-script/红线.md`，写方案和内容稿前必须读。通用的三条：不制造恐惧，不做绝对化承诺，不把没有依据的推断写成确定结论。涉及医疗、心理、法律等专业判断，一律标明边界并建议转介，不在课里下结论。
